# ALTAS Syn4 样本级特征选择诊断报告

更新日期：2026-09-16

## 1. 研究问题

Syn4 包含两个由输入自身决定的条件分支：

- 当 `feature_10 < 0` 时，标签依赖 `feature_0 × feature_1`，真实 mask 为 `0、1、10`。
- 当 `feature_10 >= 0` 时，标签依赖 `feature_2² + feature_3² + feature_4² + feature_5²`，真实 mask 为 `2、3、4、5、10`。

理想模型应对不同样本生成不同 mask。实际训练中，模型通常出现以下现象之一：

1. 所有样本选择相同的特征集合；
2. 两个分支都选择固定并集 `0–5、10`；
3. 训练早期接近关闭全部特征；
4. 后期只恢复某一个分支的特征。

本报告通过一系列逐步受控实验，定位问题来自数据可学性、预测器、生成器、Critic，还是联合训练路径。

## 2. 统一实验条件与指标

除特别说明外，实验使用：

- Syn4，20,000 个样本；
- 训练/测试比例 0.8/0.2；
- batch size 256；
- 输入维度 100，隐藏维度 64；
- 测试时分别统计 `feature_10 < 0` 与 `feature_10 >= 0`；
- 被删除的特征使用项目原有的 batch 内同列 shuffle 替换；
- 真实 mask 仅在明确标注的 oracle 诊断中用于训练，否则只用于测试评分。

核心指标包括：

- 预测交叉熵与准确率；
- 平均保留特征数；
- 负、正分支的完整真实 mask 匹配率；
- `feature_0、1` 共同采样概率；
- 路由器对两个专家的分配比例；
- 冻结模型下真实 mask、固定并集和生成 mask 的目标值。

准确率不能单独代表 mask 正确。固定并集或保留大量噪声特征也可能获得较高准确率，因此必须同时检查 mask 匹配率和稀疏程度。

## 3. 实验与结果

### 3.1 Oracle mask、固定并集和完整输入

使用相同结构分别训练只接收真实逐样本 mask、固定并集 mask 和完整输入的预测器。

| 输入 | 测试交叉熵 | 测试准确率 |
| --- | ---: | ---: |
| 真实逐样本 mask | 0.5639 | 69.11% |
| 固定并集 mask | 0.5703 | 69.05% |
| 完整 100 维输入 | 0.9937 | 58.30% |

结论：预测网络有能力利用正确的条件特征；真实 mask 比并集略优且更稀疏，但二者预测差距较小，生成器获得的区分信号天然偏弱。完整输入容易受 93 个噪声维度干扰。

对应脚本：[oracle_mask.py](oracle_mask.py)。

### 3.2 生成器的监督容量上界

直接用真实 mask 监督现有 `FeatureMaskGenerator`，只检查网络能否表达条件切换。

| seed | 测试集完整 mask 匹配率 |
| ---: | ---: |
| 42 | 88.10% |
| 43 | 88.40% |

结论：生成器结构能够表达样本级切换，问题不是网络在数学上完全无法表示正确解，而是无监督目标和联合优化没有稳定找到它。

对应脚本：[supervised_selector.py](supervised_selector.py)。

### 3.3 原始 ALTAS 的反事实 mask 对照

在同一套已训练的提取器、预测器和 Critic 下，对比真实 mask、固定并集和当前生成 mask。原训练通常在第 50 轮接近全关，之后恢复成固定单分支或并集；两个样本组仍使用相同 mask。相同冻结模型下，真实 mask 的目标值通常优于当前生成 mask。

结论：正确解并非在目标空间中完全不存在，但训练路径容易进入全关、固定单分支或固定并集等局部解。

对应脚本：[counterfactual_masks.py](counterfactual_masks.py)。

### 3.4 `feature_0、1` 的联合交互与早期暴露

负分支依赖 `feature_0 × feature_1`。单独保留其中一项几乎没有预测收益，二者必须共同保留；稀疏损失却会分别惩罚每一项。因此容易形成以下反馈：

```text
早期删除 0 或 1
→ 预测器很少同时看到二者
→ 预测器学不到乘积交互
→ 生成器更没有理由恢复二者
```

我们先用高保留率随机 mask 预训练预测器，使 `0、1` 共同出现约 81%，随后逐渐恢复稀疏权重。两个 seed 的负分支共同采样概率最终提高到约 0.81–0.85，但模型在两个分支都保留 `0–5、10`，完整 mask 匹配率仍为 0。

结论：早期成对暴露不足是问题之一，但仅保住交互会将模型从“丢特征”推向“保留并集”，不能自动产生条件切换。

对应脚本：[pair_warmup.py](pair_warmup.py)。

### 3.5 冻结合格预测器后的生成器定位

先用真实 mask 训练一个表现合格的预测器，随后冻结预测器与提取器，去掉 Critic，只训练生成器的预测损失与稀疏损失。

真实条件 mask 的目标值优于固定并集，但普通 MLP 生成器从并集附近开始训练，即使提高学习率，也很难走向条件 mask。

逐维反事实显示明显的不对称。例如 seed 42：

- 负分支删除 `feature_2`，目标仅改善约 0.0055；
- 正分支错误删除 `feature_2`，目标恶化约 0.148；
- 正分支删除 `feature_0`，目标改善约 0.0059；
- 负分支错误删除 `feature_0`，目标恶化约 0.037。

结论：在生成器尚未按条件分流时，平均梯度会强烈倾向于保留并集。错误删除另一分支关键特征的损失，远大于删除本分支冗余特征的收益。

对应脚本：[frozen_oracle_selector.py](frozen_oracle_selector.py)。

### 3.6 已知切换因子的诊断上界

诊断选择器被告知按 `feature_10` 分成两组，但不知道每组应选择哪些特征。两组 mask 仍仅通过预测损失和稀疏损失学习。

两个 seed 均在约 100 轮达到负、正分支各 100% 完整 mask 匹配。

结论：在合格预测器下，预测损失加稀疏损失能够支持正确条件解；主要困难是从共享梯度中发现并建立条件分流。该实验预先知道切换位置，只是诊断上界，不能作为最终方案。

### 3.7 Critic 消融

保留 Critic 的更新步骤，仅将生成器目标中的对抗权重从 1.0 改为 0，以尽量保持更新序列和随机数消耗一致。

| seed | 原 Critic 准确率 | 去掉生成器对抗梯度 | 变化 |
| ---: | ---: | ---: | ---: |
| 42 | 55.38% | 55.99% | +0.61 个百分点 |
| 43 | 49.75% | 57.23% | +7.48 个百分点 |
| 44 | 61.66% | 59.47% | −2.19 个百分点 |

三个 seed 的影响方向不一致；所有组的负分支完整 mask 匹配率均为 0。seed 44 无 Critic 组的正分支高匹配率来自两个分支都固定选择 `2–5、10`，不是样本级切换。

结论：Critic 会改变后期轨迹和特征偏好，但不是早期坍缩或缺少条件切换的必要原因。目前不能断言隐空间匹配无用或稳定有害。应先解决条件选择，再重新加入 Critic 衡量其对掩码、预测和隐空间匹配的独立贡献。

对应脚本：[critic_ablation.py](critic_ablation.py)。

### 3.8 不预先知道切换位置的路由器与两套专家 mask

引入一个从全部 100 维输入学习的路由器和两套独立 mask 专家，不向路由器指定 `feature_10`。普通概率加权训练能够形成路由，但少量误路由的正分支样本会污染负分支专家，因为正分支错误删除 `2–5` 的损失很大。

随后改为：

- 路由器继续使用全部样本更新；
- 每位专家只用当前分配给自己、且路由置信度最高的一半样本更新；
- 置信筛选只依赖模型输出，不使用真实分支标签。

| seed | 普通更新总体匹配 | 高置信专家更新总体匹配 |
| ---: | ---: | ---: |
| 42 | 50.00% | 96.35% |
| 43 | 49.43% | 96.23% |

两个线性路由器都自行将 `feature_10` 排为 100 个输入维度中绝对权重第 1 位。两套专家分别学出 `0、1、10` 和 `2–5、10`。

结论：不预先指定切换位置的路由器能够自行发现分支；误路由样本污染专家梯度是固定并集的重要原因，高置信专家更新能够显著缓解这一问题。

对应脚本：[learned_router.py](learned_router.py)。

### 3.9 分步移除特权信息

进一步分别移除真值并集初始化和 oracle 预测器训练。

| 预测器训练 mask | 专家初始化 | 负分支 oracle-mask CE | 负分支匹配 | 正分支匹配 | 总体匹配 |
| --- | --- | ---: | ---: | ---: | ---: |
| 真实逐样本 | 真值并集 | 0.6785 | 93.27% | 99.36% | 96.35% |
| 真实逐样本 | 100 维均匀 | 0.6785 | 93.02% | 99.46% | 96.28% |
| 随机 mask | 真值并集 | 0.6968 | 0% | 95.65% | 48.38% |
| 随机 mask | 100 维均匀 | 0.6968 | 0% | 97.53% | 49.33% |

随机 mask 预测器的负分支 CE 在 seed 43 为 0.7016；seed 42 延长到 400 轮仍为 0.6957。

结论：真值并集初始化不是关键依赖，模型可从 100 维均匀初始化找出候选特征。真正失效的是不使用真实 mask 时的预测器训练：它没有可靠学习 `feature_0、1` 的联合交互，因此负分支专家没有选择二者。

### 3.10 接回原架构的生成 mask 反馈

预测器更新改回原 `ALTASTrainer` 的形式：

```text
CE(完整输入) + 0.5 × CE(当前生成 mask 输入)
```

每批先用当前路由器和专家采样的 mask 更新任务模型，再更新路由器与专家。训练不使用真实 mask、真值并集或已知切换位置；为隔离这条反馈，暂不加入 Critic。

| seed | 第 50 轮平均保留数 | 第 400 轮负分支 oracle-mask CE | 负/正完整匹配 | 生成 mask 测试准确率 | full/masked 训练 CE |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 42 | 0.00 | 0.8094 | 0% / 0% | 60.14% | 0.393 / 0.725 |
| 43 | 0.00 | 0.8314 | 0% / 0% | 60.01% | 0.391 / 0.726 |

后期路由器最终都将 `feature_10` 学为最重要输入，但两套 mask 仍不正确。相比冻结随机预测器，当前生成 mask 上的准确率略有提高；与此同时，真实负分支 mask 下的预测能力明显恶化。

结论：原架构反馈不是没有作用，而是当前主要让预测器适应生成器给出的错误输入分布。完整输入损失快速下降，掩码输入能力及对真实条件特征的泛化没有同步改善。早期错误 mask 仍会形成生成器与预测器共同适应的坏循环。

对应脚本：[joint_router.py](joint_router.py)。

## 4. 综合结论

现有证据排除了以下简单解释：

- 不是 batch size 的首要问题；
- 不是数据完全不可学习；
- 不是预测器或生成器网络完全没有表达能力；
- 不是 Critic 单独导致全部故障；
- 不是必须依赖真值并集初始化。

目前失败由三个相互强化的环节组成：

1. **负分支交互信号弱。** `feature_0、1` 必须共同保留才有价值，单独选择任一项几乎没有收益。
2. **未分流时的平均梯度偏向并集。** 错误删除另一分支关键特征的损失，远大于删除本分支多余特征的收益。
3. **预测器与生成器可能共同进入坏循环。** 生成器早期删除 `0、1`，预测器便学不到交互；预测器学不到交互，生成器更不会恢复二者。

目前最成功的受控组合是：

```text
合格预测器
+ 不预先指定切换位置的线性路由器
+ 两套 mask 专家
+ 高置信专家更新
→ 两个 seed 均约 96% 的逐样本完整 mask 匹配率
```

该结果证明结构性解决方向可行，但还没有证明完全无特权信息的联合训练能够自行达到同样结果。

## 5. 下一阶段建议

下一阶段的首要目标不是继续单独调整路由器或立即加回 Critic，而是在不使用真实 mask 的前提下，使预测器在训练早期可靠学习负分支的联合交互，同时避免专家先全关。

建议依次验证：

1. 预测器早期同时训练于两位专家的候选 mask，而不是只服从当前路由选择，防止错误路由切断另一专家的训练信号。
2. 在预测器尚未达到负分支能力门槛前，延缓稀疏约束或设置最低保留率，避免 `0、1` 在交互形成前消失。
3. 将负分支真实 mask 下的测试 CE 是否稳定低于约 0.693 作为诊断门槛；真实 mask 只用于实验评估，不进入训练。
4. 达到门槛后启用高置信专家更新，检查能否恢复约 96% 的条件 mask 匹配。
5. 最后重新加入 Critic，分别报告 mask 质量、预测表现和隐空间匹配程度，而不是仅比较准确率或总损失。

## 6. 结果适用边界

- 多数关键结论来自 Syn4 和少量随机种子，不等同于对所有数据集的统计显著结论。
- 双专家与接近 50/50 的路由平衡利用了 Syn4 的已知实验结构；未知分支数或严重不平衡数据需要额外设计。
- Oracle 实验是故障定位工具，不是部署方案。
- 正确 mask、最高预测准确率和最佳隐空间匹配是不同指标，不能互相替代。
- 主训练代码尚未修改；所有实验均位于 `diagnostics/`。
